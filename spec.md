# Specification: Weekly Study Tracker
## Requirement: Автономность
Приложение MUST состоять из одного файла `tracker-v2.html`.
CSS и JavaScript MUST находиться внутри файла.
Приложение MUST работать без CDN, внешних библиотек, API-ключей и сетевых запросов.
### Scenario: Автономное открытие
- WHEN пользователь открывает `tracker-v2.html` в браузере
- THEN интерфейс мини-трекера доступен без загрузки внешних ресурсов.
## Requirement: Модель задачи
Каждая задача MUST содержать поля:
- `id` — уникальный идентификатор;
- `title` — название;
- `hours` — количество часов;
- `done` — логический статус выполнения.
Начальное состояние MUST содержать:
- Чтение: 2 ч, done=true;
- Практика: 4 ч, done=false;
- Повторение: 2 ч, done=false.
### Scenario: Начальная загрузка
- WHEN приложение открыто с начальными данными
- THEN отображаются три задачи
- AND всего запланировано 8 ч
- AND выполнено 2 ч
- AND прогресс равен 25%.
## Requirement: Изменение задач
Добавление, удаление и переключение `done` MUST изменять данные приложения.
После изменения данных список и показатели MUST обновляться.
### Scenario: Добавление
- WHEN пользователь вводит корректное название и часы и нажимает кнопку добавления
- THEN новая задача появляется в данных и соответствующем отфильтрованном списке
- AND общие показатели пересчитываются.
### Scenario: Удаление
- WHEN пользователь удаляет задачу
- THEN задача исключается из данных
- AND показатели пересчитываются.
### Scenario: Переключение статуса
- WHEN пользователь переключает `done` задачи
- THEN значение `done` изменяется на противоположное
- AND показатели пересчитываются.
## Requirement: Валидация формы
Приложение MUST проверять ввод до добавления задачи.
Название MUST быть непустым после `trim()`.
Часы MUST быть числом в диапазоне от 0,5 до 24 включительно с шагом 0,5.
Пустое значение часов MUST считаться ошибкой, а не нулём.
При ошибке приложение MUST показывать сообщение рядом с соответствующим полем и MUST сохранять введённые значения формы.
Некорректная задача MUST NOT добавляться.
### Scenario: Пустое название
- WHEN пользователь вводит название, состоящее только из пробелов
- THEN задача не добавляется
- AND рядом с полем названия отображается ошибка
- AND введённые значения сохраняются.
### Scenario: Пустые часы
- WHEN пользователь оставляет поле часов пустым
- THEN задача не добавляется
- AND рядом с полем часов отображается ошибка.
### Scenario: Отрицательные часы
- WHEN пользователь вводит отрицательное значение часов
- THEN задача не добавляется
- AND рядом с полем часов отображается ошибка.
### Scenario: Недопустимый шаг или диапазон
- WHEN пользователь вводит 0, 0,75 или 24,5 часа
- THEN задача не добавляется
- AND отображается ошибка часов.
### Scenario: Корректные границы
- WHEN пользователь вводит непустое название и 0,5 или 24 часа
- THEN задача успешно добавляется.
## Requirement: Расчёт показателей
Прогресс MUST вычисляться по формуле:
`round(100 × doneHours / totalHours)`
Где:
- `totalHours` — сумма часов всех задач;
- `doneHours` — сумма часов задач с done=true.
Если задач нет, приложение MUST показывать:
- Всего: 0 ч.
- Выполнено: 0 ч.
- Прогресс: 0%.
Результат MUST NOT содержать NaN или Infinity.
### Scenario: Выполнение «Практики»
- WHEN пользователь отмечает «Практику» выполненной в начальном наборе
- THEN выполнено 6 ч из 8 ч
- AND прогресс равен 75%.
### Scenario: Удаление всех задач
- WHEN пользователь удаляет все задачи
- THEN список пуст
- AND всего 0 ч
- AND выполнено 0 ч
- AND прогресс 0%.
## Requirement: Фильтрация
Приложение MUST поддерживать фильтры:
- Все.
- Активные.
- Выполненные.
Фильтр MUST изменять только видимый список.
Итоговые часы и прогресс MUST рассчитываться по всем задачам независимо от фильтра.
### Scenario: Фильтр активных
- WHEN пользователь включает фильтр «Активные» на начальных данных
- THEN отображаются «Практика» и «Повторение»
- AND «Чтение» скрывается
- AND общий объём остаётся 8 ч
- AND выполнено остаётся 2 ч
- AND прогресс остаётся 25%.
### Scenario: Фильтр выполненных
- WHEN пользователь включает фильтр «Выполненные» на начальных данных
- THEN отображается только «Чтение»
- AND итоговые показатели не изменяются.
## Requirement: Интерфейс
Интерфейс MUST оставаться читаемым при ширине экрана 390 px.
Горизонтальный скролл страницы MUST отсутствовать.
Все поля ввода и кнопки MUST иметь понятные подписи.
### Scenario: Узкий экран
- WHEN ширина области просмотра составляет 390 px
- THEN поля, кнопки, задачи и показатели остаются читаемыми
- AND горизонтальная прокрутка страницы отсутствует.
## Optional Requirement: Локальное сохранение
Приложение MAY сохранять задачи в `localStorage`.
Если улучшение реализовано:
- сохранённые задачи SHOULD восстанавливаться при повторном открытии;
- при недоступном хранилище приложение MUST продолжать работу в памяти;
- пользователь MUST видеть понятное сообщение о невозможности сохранения.
### Scenario: Недоступное хранилище
- WHEN доступ к `localStorage` запрещён или операция завершается ошибкой
- THEN приложение продолжает обрабатывать задачи в памяти
- AND показывает сообщение о недоступности сохранения.
### Scenario: Открытие через file://
- WHEN приложение открывается через `file://`
- THEN основная функциональность не зависит от доступности `localStorage`
- AND сохранение между перезапусками не гарантируется.
