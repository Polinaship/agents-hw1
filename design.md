# Design: Мини-трекер учебных задач
## 1. Архитектура
Приложение реализуется в одном файле `tracker-v2.html`.
Состав:
- HTML: форма, фильтры, список, показатели и сообщения.
- CSS: оформление и адаптивная компоновка.
- JavaScript: данные, операции, валидация, расчёты и обновление интерфейса.
Сервер и внешние зависимости отсутствуют.
## 2. Модель данных
Задача:
| Поле | Тип | Назначение |
|---|---|---|
| id | string | Уникальный идентификатор |
| title | string | Непустое название |
| hours | number | Часы от 0,5 до 24 |
| done | boolean | Статус выполнения |
`id` должен быть уникальным среди задач. Для новых задач допустимо использовать локальный возрастающий счётчик идентификаторов.
Начальные задачи:
| id | title | hours | done |
|---|---|---:|---|
| task-1 | Чтение | 2 | true |
| task-2 | Практика | 4 | false |
| task-3 | Повторение | 2 | false |
Значения id являются внутренними идентификаторами, не отображаемыми пользователю.
## 3. Состояние приложения
Основное состояние:
- `tasks`: массив всех задач.
- `filter`: текущий фильтр (`all`, `active`, `done`).
- `form`: введённые название и часы.
- `errors`: ошибки соответствующих полей.
Задачи хранятся в памяти в течение работы страницы.
## 4. Операции
### Добавление
1. Получить значения формы.
2. Проверить название после trim.
3. Проверить часы.
4. При ошибке сохранить ввод и показать сообщение у поля.
5. При успехе создать задачу с уникальным id и done=false.
6. Добавить задачу в массив.
7. Обновить список и показатели.
### Удаление
1. Получить id выбранной задачи.
2. Удалить задачу из массива.
3. Обновить список и показатели.
### Переключение done
1. Найти задачу по id.
2. Инвертировать done.
3. Обновить список и показатели.
### Фильтрация
- `all`: все задачи.
- `active`: задачи с done=false.
- `done`: задачи с done=true.
Фильтрация формирует только отображаемый список и не изменяет исходный массив.
## 5. Валидация
Название:
- Применить trim.
- Проверить, что результат непустой.
- Сохранить очищенное название при добавлении.
Часы:
- Проверить, что поле не пустое.
- Преобразовать введённое значение в число.
- Проверить конечность числа.
- Проверить диапазон 0,5–24 включительно.
- Проверить кратность 0,5.
Для проверки шага допустимо использовать условие:
`hours × 2` является целым числом.
При ошибке данные задачи не изменяются.
Сообщения выводятся рядом с соответствующими полями, а введённые значения не сбрасываются.
## 6. Расчёты
Общие часы:
`totalHours = sum(task.hours for all tasks)`
Выполненные часы:
`doneHours = sum(task.hours where task.done === true)`
Прогресс:
`progress = totalHours === 0 ? 0 : Math.round(100 * doneHours / totalHours)`
Расчёты всегда используют полный массив `tasks`, а не отфильтрованный список.
### Контрольные значения
| Состояние | Всего | Выполнено | Прогресс |
|---|---:|---:|---:|
| Начальное | 8 | 2 | 25% |
| Практика выполнена | 8 | 6 | 75% |
| Все задачи удалены | 0 | 0 | 0% |
## 7. Отображение
Интерфейс содержит:
- Заголовок мини-трекера.
- Поле названия с подписью.
- Поле часов с подписью.
- Кнопку добавления.
- Сообщения валидации возле полей.
- Фильтры «Все», «Активные», «Выполненные».
- Список задач с часами, статусом и удалением.
- Общие часы, выполненные часы и прогресс.
Изменение данных вызывает обновление отображения.
При переключении фильтра обновляется список, но не исходные данные и не рассчитанные показатели.
## 8. Адаптивность
Для ширины 390 px:
- Основные блоки размещаются в доступной ширине.
- Поля и кнопки остаются читаемыми.
- Длинные названия задач могут переноситься.
- Элементы не должны выходить за границы экрана.
- Горизонтальная прокрутка страницы отсутствует.
## 9. Необязательное хранение
При реализации `localStorage`:
1. При старте попытаться прочитать сохранённые задачи.
2. Если корректные сохранённые данные существуют, использовать их.
3. Если сохранённых данных нет, использовать начальный пример.
4. После изменений пытаться сохранять массив.
5. Ошибки чтения и записи перехватывать.
6. При ошибках продолжать работу в памяти и сообщать об ограничении.
Пустой сохранённый массив является допустимым состоянием и не должен заменяться начальными задачами.
При использовании `file://` браузеры могут по-разному ограничивать доступ к `localStorage`. Сохранение между открытиями не гарантируется.
Это улучшение не входит в обязательный объём.
